# MOMO 事务所 — 创意互动工作室

为它做一个小世界。
完整可运行的中文品牌官网 + 十七款真实可玩的宠物互动游戏。纯静态：HTML5 / CSS3 / ES6+ / Canvas / localStorage，无后端、无付费依赖，可直接部署到 GitHub Pages 子目录。

游戏里的猫一律是客户家那只真猫（`assets/pets/realcat/body.webp`，一张正脸坐姿实拍抠图），道具一律是实物抠图（`assets/props/`），列表封面也是真猫照片合成——不用手绘假猫，也不用在线生图。详见下面的「真猫渲染层」。

## 本地运行

任意静态服务器均可，例如：

```
npx serve .
# 或
python -m http.server 8010
```

然后打开 `http://localhost:8010/momo-lab/`（路径取决于服务器根目录）。

注意：直接双击以 `file://` 打开时，页面与游戏逻辑可运行，但浏览器安全策略禁止 Canvas 导出含本地图片的 PNG（表情包/分享卡会给出提示）。请改用本地服务器或上传照片，或在 GitHub Pages 上使用——导出完全正常。

## GitHub Pages 部署

仓库根目录为 `game/`（即 meicat 仓库）。本站位于其子目录 `momo-lab/`，所有资源均使用相对路径，子目录部署无需改动：

1. 提交并推送 `momo-lab/` 目录。
2. 仓库 Settings → Pages → 选择分支根目录。
3. 访问 `https://<用户名>.github.io/<仓库名>/momo-lab/`。

## 宠物定制配置

每位客户一个 JSON：`data/pets/petXXX.json`，字段：
`petId / petName / petType / petAvatar / petExpressions / petBackground / petDescription / gameSettings / customText`。

- 新建 `pet/petXXX/index.html`（复制 pet001 模板，改 `data-pet`）。
- 素材放入 `assets/pets/petXXX/`。
- 游戏页通过 `?pet=petXXX` 读取配置；专属页只展示该客户信息。
- `gameSettings` 控制专属页显示哪些游戏；`customText` 会追加进表情包预设文案。
- 3D 角色再加 3 个字段：`modelUrl`（客户 GLB）、`furColor`、`shapeParams`（脸宽/胖瘦/耳距）。缺 `modelUrl` 时角色层自动用程序化占位猫，页面照常可玩。
- `file://` 环境无法 fetch JSON 时，自动回退到 `js/core.js` 内置的同名配置。

## 游戏系统

统一状态机 READY / PLAYING / PAUSED / FINISHED；导航齿轮提供全站音效 / 动画开关（localStorage 持久化）；P / Esc 暂停；切后台自动暂停；成绩与最佳记录存 localStorage；中途离开不写脏数据。

- 紧急撤离：拖拽 / 连点 / 按住拖 / 修复贴纸四种操作；随机事件 A–E；装睡四选一；S/A/B/C + 隐藏结局；每局随机布局；分享卡。
- 混乱现场：10 物品独立动作与次数；4 组连招；6 种随机事件；连击倍率；五档评级；4 隐藏成就。
- 表情包制造机：上传照片或角色素材（自动抠白底）；8+ 预设文案、自定义文字；8 贴纸可拖动/双击删除；文字位置/字体/颜色；Canvas 真实导出 PNG。
- 谁是老板：4 场景 ×3 选择；权限/耐心/自由三数值；5 种结局均可达成；键盘 A/B/C。
- 零食危机：Canvas 接物；5 奖励 5 危险；生命/连击/加分；连续失误生气表情；末 10 秒加速；触摸 + 方向键。

## 移动端 App 外壳

四个页面（`index / games / collection / settings`）带 `data-app="1"`，`ML.chrome()` 因此只注入底部 `.ml-tabbar`，不注入网页版导航与页脚——游戏页和品牌页仍是原来的顶栏 + 页脚，两套外壳互不干扰。四个 tab 是真链接真路由，不是假切换。

数据全部来自本机 localStorage，首页显示的不是写死的数字：

| 键 | 内容 |
|---|---|
| `ml-stats` | 互动次数 / 积分 / 开过的局 / 表情包数 / 换装数 |
| `ml-records` | 每款游戏的 best 与 plays |
| `ml-works` | 收藏作品（≤60 条，含 PNG dataURL、来源游戏、标题、日期） |
| `ml-daily` | 今日任务：以当天第一次打开时的累计值为基线，跨天自动归零 |
| `ml-dressup` | 换装室搭配记忆 |

撸猫（首页主视觉点击）加互动次数并弹表情贴纸；任意游戏开局加「开过的局」；导出表情包 / 换装图加对应计数并可写进 `ml-works`；任务领奖励才加积分。设置页可分别重置今日任务、清空作品、清空全部数据。

## 真猫渲染层（`js/cat-rig.js`）

客户的要求很直接：游戏里的猫必须是我家那只，东西必须是真东西。所以十款游戏（jump / sneak / dressup / kitten / laser / hidecat / slingshot / static / parkour / meowtalk）都不再画猫，而是把 `assets/pets/realcat/body.webp` 这一张正脸坐姿实拍抠图按舞台变换摆进去。

**只有一张图，这是素材现状不是设计选择。** 附件里能干净抠出全身的只有这一张，其余照片要么猫贴着画面边、要么背景太碎，抠完会带一块地板。所以：

- `P_HEAD` / `P_TAIL` 现在只是指向同一张照片的坐标别名，让换装、找猫这类「按部位摆东西」的代码还能共用同一套 `apply()` 数学；它们不是独立的层。
- 眨眼、张嘴、炸毛尾巴这些原本靠分层贴片做的动画，在没有对应实拍图之前一律不画，`CatRig` 里是空操作。宁可不动，也不用画出来的五官去补。
- **几何只有一张表**：每个部位记 `size`（原图尺寸）、`anchor`（旋转/缩放围绕的那一点在原图哪个像素）、`at`（这块在 480×560 舞台上的落点）、`s`（缩放）。变换顺序 `at ← rot ← scale ← (−anchor)`，所以「锚点永远落在 `at + 位移` 上」——换装室的领口、弹弓的嘴圈都靠这条不变式对齐，改角度不会把贴片甩飞。
- **五官贴片暂时不画**：`P_FACE` 只保留 `at[1]`（眼线在舞台上的高度）给需要引用脸部位置的页面用，`blink` / `mouth` 在没有实拍表情图之前是空操作。
- **命中用 alpha 蒙版**：`masks` 是按 alpha 降采样出来的点阵，`CatRig.hit()` 判「摸到的是猫还是背景」，不是套一个矩形框。
- **`CatRig.box(gx, gy, gw)` 是十款游戏共用的外壳**：给一个舞台盒，返回 `draw / hit / p / at`，游戏只管自己的坐标，缩放和分层由这里做。姿态一律从 `CatRig.pose({...})` 出来，缩放、歪头、前倾是真在动的；呼吸只动整体缩放，眨眼和张嘴要额外素材（见「待补素材」）。
- **图没到位不装死**：`CatRig.load()` 失败时页面给出中文提示（`file://` 下要改用本地服务器），不会画一只假猫顶上。

道具同理，全部是 `assets/props/` 里的实拍抠图：家务杂物 8 张（扫把 / 吹风机 / 垃圾桶 / 洗衣液 / 扫地机器人 / 袜子 / 礼物盒 / 零食袋）+ 零食玩具 8 张（零食盘 / 肉条 / 猫粮 / 饼干 / 小鱼 / 零食球 / 掉落球 / 玩具鱼）。名字一律跟着照片里真正拍到的东西走——`prop-pillow.png` 拍的其实是零食袋，所以游戏里就叫它零食袋，文件名不作数。

列表封面 `assets/covers/*.jpg`（17 张，320×240）也不是另画的：`_scratch` 侧的 `covers3.py` 用同一张 `body.webp`、同一套 `cat-rig` 几何和 `assets/props/` 真图当场合成，所以列表里的猫和游戏里的猫是同一只。代价是 17 张封面全是同一个正脸坐姿——只有一张照片，镜像也救不回来，要分出「警觉 / 打哈欠 / 眯眼」得先有对应的实拍图（见「待补素材」）。

**还留在 canvas 里画的**（如实说明）：追红点的红点、静电吸毛的火花与毛球、弹弓的皮筋与轨迹、跑酷远景的挂画 / 置物架 / 吊灯——这些要么是光，要么是抽象特效，没有对应的实物照片。要换成真图得先有实拍素材。

## 3D 角色层（游戏 06 宠物世界）

同一套接口两条渲染路径：有客户 GLB 就播它的骨骼动画与形态键，没有就用 `js/pet3d.js` 里的程序化占位猫（28 根契约骨骼 + 参数化动作 + 变换驱动的五官）。二者共用同一份表情参数与事件表，所以 GLB 到货只是多一个文件名。

- 身体 / 表情 / 尾巴 / 耳朵四层独立：奔跑中可以翻脸，炸毛不影响腿。
- 游戏不碰骨骼：`ML.sound` 的 8 个音效点同时是 8 个角色事件（`ML.onSound` 转发，五款游戏零改动），点击身体按头/身/尾/掌四个分区给不同反应。
- 手机优先：像素比上限 1.5、连续掉帧自动降采样、切后台暂停、`dispose()` 释放几何体/材质/贴图、一次性离屏渲染导出透明 PNG 表情包素材（`preserveDrawingBuffer` 只在导出那一帧开）。
- `tools/glb-check.html`：把外包 / AI 生成的 `.glb` 拖进去，浏览器本地解析，按契约给"通过 / 不通过"，并能在没有真模型时先用占位角色跑一次"导出 → 重新加载 → 渲染"验证通路。
- 完整规格、AI 生产管线与验收清单见 `docs/pet-character-spec.md`。
- three r169 已 vendored 在 `js/vendor/`，无 CDN、无构建步骤；但该页用 ES 模块 + importmap，多数浏览器双击以 `file://` 打开会拦下模块加载——页面会显示中文提示而不是白屏，请用本地服务器或线上地址访问。

## 移动端

断点 960 / 720，按 390×844 校准：导航收进抽屉（含「开始一个项目」入口）、单列栅格、`html{overflow-x:clip}` 杜绝横滚、按钮与选项最小 44px 触摸目标、输入框 16px 防止 iOS 聚焦自动缩放、场景与画布高度按屏收窄、`@media(hover:none)` 关掉悬停位移、底部留 `env(safe-area-inset-bottom)` 安全区。游戏在触屏下用 Pointer 事件操作：拖拽、连点、长按拖动均可用，切后台自动暂停。

## 素材

assets 内图片来自客户提供的附件与既有渲染素材，未使用在线生成服务（全站零生图、零积分消耗）。角色 PNG 的白底由 `js/core.js` 的运行时抠图处理；附件右下角水印在主视觉中以裁切方式避开。

- `assets/pets/realcat/body.webp` 是客户真猫的一张正脸坐姿抠图（390×472），十款游戏 + 17 张列表封面都由它合成，别再用画出来的猫。抠图流程在 `_scratch/matte_fix.py`：先用色度把左下角漏进来的地面切掉，再在爪尖接触线（照片 y≈462）以下全部清空，否则猫会站在一块亮地板上。
- `assets/props/` 是家里实物抠图，道具命名跟着照片里真正拍到的东西走；抠图必须一件一张，两张拍进同一张图里（扫把和吹风机曾经混过）会让游戏里的标签和画面对不上。
- `assets/dressup/` 是 6 件真图衣裳，接图口子见 `assets/dressup/README.md`；没有真图的卡片显示占位图标并且拒绝穿上，不做「穿了却看不见」的假效果。
- **换图要一起改版本号**：`js/core.js` 的 `asset()` 会把自己 `<script>` 上的 `?v=N` 转给每个素材路径，所以换完 `body.webp` 或任何一张素材，要把 28 个 HTML 里 `?v=N` 的 N 一起 +1，否则老访客（和我自己的测试页）继续吃缓存里的旧图。

## 待补素材（按优先级，附提示词）

下面这些是**现在代码里做不到真、又不肯拿画出来的东西糊弄**的地方。每张图的要求都写在后面，照着生成就行；生成完不用改名、不用抠图，直接按文件名丢进对应目录，我把 `?v=` 一升就能上。

### ① 猫本体 6 张（最高优先级，缺了就只能用一张坐姿图）

统一要求：**同一只金渐层英短、同一个机位、相机与猫眼同高、纯 `#00FF00` 绿幕背景、全身完整入框且四周各留 ≥10% 空白（千万别贴着画面边，一贴边就抠不干净）**，不要美颜、不要画上去的眼线、不要任何文字或水印。

| 文件名 | 内容 |
| --- | --- |
| `body-sit-front.png` | 正面端坐，两只前爪并排朝前，尾巴收在身体右侧可见 |
| `body-sit-side.png` | 左侧面朝镜头的自然站姿，四腿完整、尾巴完整翘起 |
| `body-loaf.png` | 农民揣趴姿，正面，尾巴绕到前爪边 |
| `body-pounce.png` | 前爪离地扑过来的瞬间，侧面朝左 |
| `face-blink.png` | 和 `body-sit-front.png` **完全同一个姿势同一个位置，只是眼睛闭上** |
| `face-yawn.png` | 同上，只是嘴张大打哈欠 |

提示词（逐条替换最后一句即可）：

```
真实宠物摄影，一只金渐层英国短毛猫，奶油金色短毛、圆脸、耳朵小而圆、
眼睛大而圆呈黄绿色。影棚拍摄，50mm 定焦，相机与猫眼同高，
纯均匀绿幕背景 #00FF00，光线柔和均匀，猫身上不要有绿色反光。
猫完整入框，画面四周各留 10% 以上空白，不要裁到身体任何部位。
不要美颜磨皮，不要画上去的眼线睫毛，不要文字水印，不要道具。
姿势：<正面端坐，两只前爪并排放在身前，尾巴收在身体右侧，完整可见>
```

`face-blink` / `face-yawn` 这两张如果能和 `body-sit-front` 用连拍（同一 tripod 同一位置连按），效果最好——游戏里的眨眼是整张图替换，姿势差一点就会「一闪变成另一只猫」。

### ② 换装 6 件（现在的图贴上去像给猫穿了娃衣）

问题出在图本身：现在这 6 张是**站姿宠物服的平铺商品图，接近正方形**，而游戏里的猫是正面坐姿，能露出来的胸口只有大约 178×300 像素的一块，横比竖宽。按高度塞进去，衣服就只有 150 来宽，看着像摆在胸前而不是穿在身上。

重生成时统一要求：**纯白背景、单件、不要猫、不要模特、不要吊牌文字**，并且**形状要横向比纵向宽（比例约 1.6 : 1）**，按"从正面看一只坐着的猫穿上的样子"来画：

```
宠物服装产品照片，纯白背景，单件平铺，画面里不要出现猫、模特、吊牌和任何文字。
这件衣服是按「正面端坐的猫穿上后从正前方看到的样子」设计的：
整体横向比纵向宽，比例约 1.6:1，上沿是贴合脖子的弧形领口，
下沿是绕着胸口的圆弧，下方中央留出两个前爪伸出来的开口，不要长袖垂下来。
材质与光线：<针织毛衣，淡粉色，柔光箱布光，能看到针织纹路>
```

六件分别替换材质那句：`淡粉针织毛衣` / `黄色连帽卫衣，帽子摊在背后可见` / `格纹围巾，只要围成一圈的那一段，不要两条长飘带` / `粉色缎面领结` / `深藏蓝贝雷帽，只要帽体，帽檐朝下，绝对不要缝上去的猫耳朵` / `薯饼造型连帽衫，黄色格纹`。

帽子那张尤其重要：现在这张图里两只布耳朵是缝死的，盖在真猫耳朵上会变成四只耳朵，我只能裁掉半张图。
