# MOMO LAB · 3D 宠物角色规格与生产管线

给接单用的交付规格。**目标不是"会用 Blender"，而是"AI 出初稿 + 人工只补表情 + 骨架命名不跑偏"。**
本文件里的命名是**契约**：`js/pet3d.js` 按这些名字找骨骼、动画片段和形态键，名字错了角色就哑掉。

---

## 一、生产管线（一单的实际流程）

原则：**骨架和动作库做一次，永久复用；每单只做"外形 + 毛色 + 贴图"。**

| 步骤 | 谁做 | 用什么 | 产出 | 首单耗时 | 复用时 |
|---|---|---|---|---|---|
| 1 收料 | 客户 | 正面/侧面/全身/花纹细节 3–5 张，禁滤镜过曝 | 原图 | — | — |
| 2 出模 | AI | 图生 3D（多视角优先） | 带贴图的 mesh | 20 min | 跳过 |
| 3 绑骨 | AI | 四足自动绑骨 | skeleton + skin weights | 10 min | 跳过 |
| 4 套动作 | AI/库 | 预设动作库或文本生成动作 | 12 个 clip | 30 min | 跳过 |
| 5 **精修外形** | 人 | 建模软件：清理网格、修脸、确认"像不像" | 干净 mesh | 2–4 h | **每单必做** |
| 6 **做表情** | 人 | 手工形态键（6 个） | shape keys | 1–2 h | 跳过 |
| 7 重命名 | 人/脚本 | 按本文件第三节改骨骼与 clip 名 | 契约合规 GLB | 20 min | 跳过 |
| 8 自检 | 脚本 | `tools/glb-check.html` 拖进去 | 检查报告 | 1 min | 1 min |
| 9 接入 | 代码 | `data/pets/*.json` 填 `modelUrl` | 上线 | 0 | 0 |

**第 5、6 步是唯一真正的人工。** 第 5 步每单都要做（因为客户要认得出自己家猫），第 6 步只做一次。
长毛、卷毛、异瞳、超大体型在第 5 步之外另加预算，第一版只承诺**短毛猫**。

### AI 现在做不到、必须人做的三件事
1. **猫的面部形态键**。所有 AI 绑骨只给身体骨架，非人形面部 blend shape 没有任何现成方案，只能手工。
2. **还原度**。AI 会"生成一只英短"，不会"生成你家那只"。第 5 步就是为这个存在的。
3. **命名**。自动绑骨输出的骨骼名各家不同，必须映射成本契约。

### 关于授权（商用前必看）
图生 3D 服务多为**免费层署名可用、付费层才拥有产出**。在付费层之前，产出可能要标注来源。
接单定价里要包含这笔；或者走开源自托管路线（模型权重本地跑，需要显卡）。**下单前确认一次当期条款**，不要凭记忆。

## 二、性能与体积预算（手机浏览器是第一目标）

| 项目 | v1 预算 | 说明 |
|---|---|---|
| 三角面 | ≤ 20,000 | 文档建议 3–6 万是桌面标准；我们是手机网页，先压到 2 万 |
| 形态键 | **≤ 6 个** | 手机 WebGL 同屏 morph 上限常在 8，超了会静默丢弃，表情直接失效 |
| 骨骼 | ≤ 30 | 只留契约里用到的；自动绑骨常给 60+，删掉不驱动的 |
| baseColor | 1024px，webp/jpeg | 唯一必须高清的图 |
| normal / ORM | 512px | |
| GLB 体积 | ≤ 1.5 MB | 每单一个文件，直接决定 Pages 仓库大小 |
| 动画 | 30fps 采样 + keyframe 压缩 | 12 个 clip 全在同一个 GLB 里 |
| 设备像素比 | `min(dpr, 1.5)`，低端 1.0 | |
| 阴影 | 关 | 用一个假接触阴影贴图代替，视觉够，成本低 |
| 同屏实例 | 1 只 | 大厅和游戏不许同时各渲染一只 |

必须实现的运行时行为：切后台暂停、离开页面 dispose 模型和纹理、进入游戏只加载当前关卡资源、低端机自动降级到静态封面。

## 三、骨骼命名契约

只认下列名字（大小写不敏感，允许 `ml_` 前缀去掉）。找不到 `ml_head` / `ml_spine_01` / `ml_tail_01` / `ml_ear_l` / `ml_ear_r` / `ml_jaw` 就报错，不要静默兜底。

```
ml_root
└─ ml_hips
   ├─ ml_spine_01
   │  └─ ml_spine_02
   │     └─ ml_chest
   │        ├─ ml_neck
   │        │  └─ ml_head
   │        │     ├─ ml_jaw
   │        │     ├─ ml_ear_l          ml_ear_r
   │        │     └─ ml_eye_l          ml_eye_r        (眼球，只转不蒙皮权重)
   │        ├─ ml_front_leg_l                          ml_front_leg_r
   │        │   └─ ml_front_knee_l / _r
   │        │       └─ ml_front_paw_l / _r
   │        └─ ml_tail_01
   │            └─ ml_tail_02 → ml_tail_03 → ml_tail_04
   └─ ml_back_leg_l                                   ml_back_leg_r
       └─ ml_back_knee_l / _r
           └─ ml_back_paw_l / _r
```

可选补充（有就用，没有就程序近似）：`ml_shoulder_l/r`、`ml_hip_l/r`、`ml_whisker_l/r`。

**独立性要求（决定搞笑程度）**：`ml_head` 的转动、`ml_tail_01` 的摆动、四肢的位移必须能各自驱动、互不覆盖。
做不到这三路独立，就只能"坐着+发呆"，做不出"奔跑+惊恐+炸毛"。验收时专门测这一条。

## 四、形态键命名契约（就这 6 个）

自动绑骨和图生 3D 默认**不会**产出这些，需要手工做。命名 `ml_ex_*`：

| 名称 | 含义 | 权重范围 |
|---|---|---|
| `ml_ex_eye_close` | 上下眼睑完全闭合（做表情键时直接闭眼，不要半闭） | 0–1 |
| `ml_ex_eye_wide` | 眼眶张开、眼白变多（惊吓） | 0–1 |
| `ml_ex_mouth_open` | 下颌张开、口腔可见（打哈欠/叫） | 0–1 |
| `ml_ex_mouth_smile` | 嘴角上扬。**负值 = 嘴角下压（嫌弃/委屈）**，省一个键 | −1–1 |
| `ml_ex_cheek_raise` | 脸颊上抬（开心眯眼的关键） | 0–1 |
| `ml_ex_whisker_fan` | 胡须垫外扩（生气炸毛） | 0–1 |

`Brow_Inner`（眉挤压）不做键：猫没有人类眉毛，用 `ml_ear_back` 骨骼 + `eye_wide` 负值近似，硬做会像人脸。
`Blink` 不是形态键，是程序对 `eye_close` 的定时插值（参数见 `config/expressions.json`）。

## 五、表情 = 数据，不是动画

9 种基础表情全部由上面 6 个形态键 + 4 个骨骼通道组合而来，所以**同一时刻可以边跑边换表情**。

骨骼通道：`ear_back`（耳后压 0–1）、`ear_up`（耳竖起 0–1）、`head_tilt`（歪头 −1–1）、`eye_look`（视线 x/y −1–1）。

| 表情 | eye_close | eye_wide | mouth_open | mouth_smile | cheek_raise | whisker_fan | ear_back | ear_up | head_tilt |
|---|---|---|---|---|---|---|---|---|---|
| normal 正常 | 0 | 0 | 0 | 0 | 0 | 0 | 0 | .2 | 0 |
| happy 开心 | .3 | 0 | .2 | .8 | .7 | 0 | 0 | .3 | .1 |
| shock 震惊 | 0 | 1 | .7 | −.2 | 0 | 0 | .5 | 0 | −.1 |
| disgust 嫌弃 | .8 | 0 | 0 | −.5 | 0 | 0 | .3 | 0 | −.15 |
| angry 生气 | 0 | .4 | .1 | −.8 | 0 | 1 | 1 | 0 | −.2 |
| sad 委屈 | .4 | 0 | 0 | −.6 | 0 | 0 | .6 | 0 | .25 |
| confused 疑惑 | 0 | .2 | 0 | 0 | 0 | .2 | .1 | .5 | .6 |
| sleepy 困倦 | .7 | −.3 | .15 | −.2 | 0 | 0 | .4 | 0 | .3 |
| smug 得意 | .5 | 0 | 0 | .6 | .3 | 0 | 0 | .4 | −.3 |

数值是起点，必须在真模型上过一遍再定稿。**这就是第 6 步人工要交付的东西**：一张填好的表，不是几十段动画。

## 六、动画片段命名契约（12 个）

clip 名必须完全一致，程序按名字取；缺哪个哪个动作就不播（不报错，但会在自检里出现）。

| 组 | clip | 用途 |
|---|---|---|
| 日常 | `ml_idle` | 待机，必须可无缝循环（大厅） |
| | `ml_walk` | 行走 |
| | `ml_look_around` | 转头观察 + 耳朵转 |
| 动态 | `ml_run` | 奔跑 |
| | `ml_jump` | 蹬地跳跃 |
| | `ml_roll` | 翻滚后回正 |
| 互动 | `ml_pet` | 被摸头，闭眼享受 |
| | `ml_poke` | 被戳后躲开 |
| | `ml_stretch` | 伸懒腰 |
| 搞笑 | `ml_shock` | 受惊弹起 |
| | `ml_angry` | 炸毛甩尾 |
| | `ml_collapse` | 夸张瘫倒 |

建议补：`ml_sit`、`ml_victory`（结算姿势）。
`ml_idle` 的循环点必须干净——它是玩家看得最久的一段。

**只有骨骼、还没有动作片段也能跑。** 控制器发现 GLB 里一个 clip 都没有、但 `ml_*` 骨骼齐全时，
会自动用和占位角色同一套程序化动作直接驱动这些骨骼（自检页会提示"已用程序化动作驱动其骨骼"）。
这意味着第一单可以先只交付"改名 + 绑骨"的 GLB 就把角色接进网页，动作片段作为第二期补上；
一旦补了 clip，程序立刻切回真动画，代码不用动。

## 七、游戏事件 → 角色反应映射

游戏侧**不碰骨骼**，只发事件。事件源就是现有的 8 个音效函数（`js/core.js` 的 `ML.sound`），
在 `ML` 里转发一次，五款游戏一行都不用改。

| 事件（现有音效） | body | face | tail | 已存在的调用点数 |
|---|---|---|---|---|
| `tap` 玩家点击 | ml_poke | disgust | sway | 6 |
| `good` 做对了 | ml_jump | happy | fast | 5 |
| `bad` 撞了/弄错 | ml_shock | confused | puffed | 8 |
| `combo(n)` 连击 | ml_look_around | smug | fast | 2 |
| `bonus` 奖励 | ml_jump | happy | fast | 6 |
| `win` 胜利 | ml_victory→ml_jump | smug | fast | 4 |
| `lose` 失败 | ml_collapse | sad | still | 3 |
| `tick` 倒计时 | ml_stretch→ml_idle | sleepy | sway | 3 |

调用形式（项目自定义接口，不是 Three.js 自带）：

```js
pet.play({ body: "ml_collapse", face: "sad", tail: "still", duration: 1.8, returnTo: "ml_idle" });
```

`returnTo` 是必须的：动作播完回 `ml_idle`，否则角色会卡在最后一帧，立刻穿帮。

**点身体的哪个部位决定反应。** 控制器从命中的网格往上回溯，先看 `userData.zone`，没有就按骨骼名归类：
头/下巴/耳/眼 → `head`，尾 → `tail`，腿/膝/掌 → `paw`，根/臀/脊/胸/颈 → `body`。
所以真 GLB 不需要在 Blender 里做任何交互标记，只要骨骼名守契约，点击分区就生效。
四个分区各自的反应在页面里配置（大厅用：头=被摸头/开心，身=伸懒腰/得意，尾=炸毛/生气，掌=被戳/嫌弃）。

## 八、目录与配置

```
momo-lab/
├── js/vendor/three.module.min.js      r169, MIT, 已内置
├── js/vendor/addons/{loaders,exporters,utils}/
├── js/pet3d.js                        PetController + GLB 适配器 + 占位角色
├── game/pet-world.html                游戏 06：角色大厅 demo（表情/动作/事件/点击分区/导出）
├── tools/glb-check.html               交付验收：拖入 .glb 本地体检 + 内置通路自检
├── assets/models/pet001.glb           每单一个
├── assets/textures/pet001/*.webp      仅当贴图不在 GLB 内时
└── data/pets/pet001.json              加 3 个字段（见下）
```

`tools/glb-check.html` 不上传文件，浏览器里解析完直接给"通过/不通过"表；页面里还有一个
"用占位角色跑一次 GLB 通路自检"按钮——它把内置角色导成真 GLB、再重新加载渲染，
用来证明"导出 → 加载 → 渲染"这条路本身没问题，和外包交付的模型质量是两件事。

自检输出分两类，别混：`missing` 只写契约缺口（缺哪根骨、缺哪个 clip），
`warnings` 写运行时降级（帧率不足降像素比、GLB 无片段改用程序化动作）。

`data/pets/*.json` 新增字段（缺 `modelUrl` 时自动退回占位角色，页面不会白屏）：

```json
{
  "modelUrl": "assets/models/pet001.glb",
  "furColor": "#E8A857",
  "shapeParams": { "headWidth": 1.0, "bodyFat": 1.15, "earSpread": 0.9 }
}
```

`shapeParams` 是"每单只改参数不改模型"的落点：脸宽、胖瘦、耳距三个标量，程序直接缩放对应骨骼。

## 九、验收清单

### 角色本体
- [ ] 正面 / 侧面 / 背面 / 四分之三 四个角度看过
- [ ] **客户一眼认出自己的宠物**，而不是"像某种猫"
- [ ] 眼睛颜色、花纹走向、耳距、体型四项与客户照片一致
- [ ] `ml_idle` 循环无跳帧；随机眨眼、视线跟随、耳朵微动都在跑（静止的角色像展示模型，不像活物）

### 骨架
- [ ] 头部 / 尾巴 / 四肢三路可独立驱动
- [ ] 跳跃时身体弯曲 + 后腿蹬 + 前腿伸 + 尾平衡，不是整体平移
- [ ] 蒙皮无破面：极端姿势下腋下、髋部不出现撕裂

### 表情
- [ ] 形态键 ≤ 6 个，名字全部符合契约
- [ ] **在 `ml_run` 播放中能切换表情**（这是"数据不是动画"的证据）
- [ ] 9 种表情在手机尺寸下能分辨——眯眼和困倦看不出区别就得重做

### 性能（真机，不是模拟器）
- [ ] 中端安卓机 ≥ 30fps 稳定，无发热掉帧
- [ ] GLB ≤ 1.5MB，加载 ≤ 3s（4G）
- [ ] 页面切后台暂停、离开页面释放纹理
- [ ] `file://` 直开时不白屏（ES module 在 file:// 下会被 CORS 拦，必须走降级）

### 接入
- [ ] `tools/glb-check.html` 拖入 GLB，报告全绿
- [ ] 事件映射表里 8 个事件都验证过一次

## 十、分阶段（第一单不要做完 12 动作 9 表情）

1. **一只测试猫**：外形 + 毛发材质 + 正侧背效果。验收：**不看名字能认出它**。
2. **基础骨骼**：头/身/四肢/尾/耳。验收：能自然走路、坐下、跳跃、转头。
3. **面部表情**：先只做 正常/开心/震惊/嫌弃/委屈 五种。验收：跑动中能独立换表情。
4. **接入网页**：占位角色已被 `js/pet3d.js` 驱动，这一步只是换成真 GLB。验收：手机流畅。
5. **接入游戏与表情包**：事件驱动 + 离屏渲染导出透明 PNG。验收：同一只猫贯穿全站。

**第一版技术目标定为：一只精致 3D 宠物、五种表情、五种动作、可互动的网页角色。**
动物只做短毛猫一种；长毛猫和狗等猫咪线稳定后再开。
